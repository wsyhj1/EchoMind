## 已修复的评测导出问题

原始阶段3四条QA记录的 `final_parent_ids` 均只有3项，而末轮 ToolMessage 和 trace 中实际有5项。Q045漏掉 `order_ownership.pdf` 及另一份职责PDF；Q086漏掉 `history.pdf` 和 `order_ownership.pdf`。这会让Q045外层完整证据指标错误地成为0；模型实际看到了架构、职责和操作流程三个必要来源。

根因是 `evaluation.engine.final_knowledge` 使用 `context['text'] in tool_content` 验证原文可见性。结构化工具把PDF原文中的真实换行编码为JSON的 `\n`，直接字符串查找失败。不是模型没拿到证据，也不是父块去重错误。

共享评测函数现先解码顶层 `evidence` 列表，再核对原文、文件名与知识库；普通旧版工具文本仍按原文匹配。只读trace的可见标记不够，必须同时存在于末轮真实工具消息。任意JSON元数据、错误文件或库、早前轮次的工具内容不能冒充本轮来源。忠实度支持上下文使用同一解码逻辑。新增8个回归测试，加原评测7项合计15项通过；修复前已复现换行与引号转义两个失败。

原始 `qa_final.jsonl`、`qa_delivery.jsonl` 与 `qa_graph.jsonl` 不覆盖。[更正审计JSON](04_qa_export_correction_audit.json)逐次保存旧/更正来源列表和指标。此为离线更正，不冒充重新执行Agent。四组A/B/C/D检索由独立检索导出路径产生，400条指标重新计算与原始记录全部一致；不能因QA导出缺陷否认该组检索指标。

为后续真实回答实验补充的 `answer_eval` 汇总记录执行前/后源码SHA256、数据SHA256与是否保持不变、图谱及检查开关、Gold状态计数。数据中 `agent_reviewed`、`pending_human_review`、缺失或混合状态按原样区分，回答质量指标保持null，等待独立答案审核。另有3项溯源测试，与上述15项合计18项通过。
