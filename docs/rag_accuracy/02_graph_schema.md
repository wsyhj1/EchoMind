# PostgreSQL 证据图实现

第二阶段继续使用 Milvus dense/BM25/RRF、PostgreSQL 父块和现有 Reranker。
图谱只提供候选原文及关系链，不生成答案，不索引记忆或画像。

## 表与一致性

迁移 `backend/migrations/003_knowledge_graph.sql` 由 `GraphRepository.initialize` 执行。
事务内使用当前 schema 的 advisory lock，`kg_schema_migrations` 保存 SHA256。
重复与多实例并发执行安全；已应用脚本若被修改会拒绝执行，后续改表应新增迁移。
默认关闭图谱时启动不会创建这些表。在线查询不做 DDL，缺表直接回退。

| 表 | 用途与隔离 |
|---|---|
| kg_entities | 用户、知识库、类型、规范化名称及真实消歧限定词共同定义实体，UUID5 稳定生成 |
| kg_relations | 有方向的白名单关系；两端实体均通过复合外键限制在同一用户、知识库；按抽取版本去重 |
| kg_relation_evidence | 原文 quote、父块、文件、作业；复合外键同时核对父块身份与实际文件，防止串源 |
| kg_entity_mentions | 当前父块的实体提及，支持候选父块补充种子；绑定作业和版本 |
| kg_index_jobs | 文件+用户+知识库+版本唯一，保存状态、租约、尝试次数和质量统计 |
| kb_delete_tasks | PG 删除事务内写入的 Milvus 补偿任务，无被删除文件/知识库外键 |

一条事实可有多份文件证据。删除文件只级联删除其作业、提及和证据；随后清理零证据关系和孤立实体。
实体不会跨用户或知识库物理合并。“默认知识库”只在查询时解释为当前用户的授权范围，禁止用于入库。

## 抽取与索引

上传完成原父块和向量写入后，`GRAPH_EXTRACTION_ENABLED=true` 时入队。
独立后台 worker 从 PG 认领作业，LLM 调用在事务外，文件全部父块成功后在一个事务内发布。
事务再次核对租约、源父块及全文，最后才写 READY。半份抽取不会作为完成索引上线。

作业流转：PENDING → RUNNING → READY / FAILED；进程中断留有 120 秒租约，30 秒心跳续约。
过期 RUNNING 最多自动认领 3 次。FAILED 需要显式 `--force` 重试；失败批次立即停止，worker 延迟下一次尝试。
删除源文件会删除作业，使迟到的发布失去租约/外键而失败。

抽取复用 `BASE_URL`、`DASHSCOPE_API_KEY`，默认使用 `AGENT_BASE_MODEL`，可单独配置 `GRAPH_EXTRACTION_MODEL`。
最初后台模型实测返回 429，因此改为已验证可用的主模型作为新功能默认值；原聊天/记忆模型配置不变。
每父块最多 2 次尝试，单次默认 30 秒；父块并发默认 4，每文件最多 1000 父块。
作业质量统计中的 entities/relations 是父块抽取出现次数；物理去重后的图规模应另外查询统计。
Schema 限制 48 个实体、64 条关系，拒绝额外字段、非法类型和任意 SQL 谓词。

所有接受的关系均要求当前肯定状态、原文可定位的 quote、引用内出现两个端点、合法实体类型与关系方向。
历史/计划/否定/不确定关系不进入在线图；拒绝数计入索引统计。
这属于保守文本证据校验，不能保证 LLM 语义判断绝无错误，正式效果仍需审核标注。

v1 的真实试验发现“独立实例”和“实例”被模型误用为身份限定词，切断跨文档路径。
v2 忽略通用及与全名重复的限定词；地区、账号、环境等真实消歧信息仍保留。
不按相似名称做全局模糊合并；同名不同限定词的歧义节点保留，链接无法消歧时跳过。

## 在线检索与融合

规则判断关系意图，优先在数据库内匹配 Query 明确名称/合法别名。
无明确匹配或存在歧义时，从向量候选父块的提及补充种子。
Redis 技术概念与通用别名不会作为具体实例种子。
显式历史、非当前年份、未来或计划问题跳过当前事实图，继续原检索。

最多 3 个种子、2 跳、20 条被访问关系、5 个证据父块，默认总图查询超时 400ms。
采用固定的有方向关系模板，包括 USES→MAINTAINED_BY、DEPENDS_ON→MAINTAINED_BY 和 HAS_ISSUE→RESOLVED_BY。
每跳都要求 READY 作业、当前版本、有效证据及实际父块；不拼接模型 SQL，不跨知识库连边。
同一事实多份来源时选一份有效证据；删除后可改用另一份。

融合按 `(user_id, knowledge_base_id, parent_id)` 去重，来源和关系 ID 合并。
Reranker 输入仍限制 min(3K,30)，图证据替换输入末尾候选，不提高原重排预算。
最终最多按 `GRAPH_BRIDGE_QUOTA` 保留一条/少量完整路径，默认 2 个父块，其余位置按统一重排填充。
路径若容不下就不强塞半条链。图谱报错、超时、无证据、索引缺失均保持向量链路可用。
工具字符串和 Prompt 不变；内部 trace 保存路径、来源、耗时及降级信息。

## 重复内容与删除补偿

原系统跨文件跳过重复子块，造成第二份文件没有自己的向量入口。
现在每个文件/父块保留来源行；同父块内重复子块仍去重，文件哈希去重保留。
向量化按不同文本去重，并在相同用户、知识库内尝试复用已有 embedding，复用失败时正常计算。
代价是 Milvus 保留更多来源行；这是溯源和单文件删除正确性需要的存储开销。

PG 文件/知识库删除、图谱清理和补偿任务入队在一个事务内提交。
原 API 随后删除 Milvus，成功确认任务 DONE，失败仍返回错误并保留 PENDING。
worker 幂等重试，最多 5 次；用 CLI 可显式重置失败预算。
清理尚未完成时禁止向该知识库上传或重建同名知识库，避免迟到的删除清掉新来源。
关闭图谱抽取后，已存在的删除补偿 worker 继续工作。
应用退出先取消后台写入任务，再关闭连接，未完成图谱作业可按租约恢复。

PG 与 Milvus 仍无共同事务。并发上传/删除的极端竞态及首次入队失败可通过回填修复；
在线父块核对会排除残留向量命中。没有把 `asyncio.gather` 当成跨库原子事务。
