1. A/Q041写“知识库中未明确记载订单系统使用的具体缓存名称”，但同一末轮 `order_architecture.docx` 已明确订单使用赤霄，回答后半段也承认这一点。这是真实矛盾，不能按合理保守拒答处理。
2. A/Q093正确说明2027未知，但额外把2026的“青岚缓存集群由支付平台乙组维护”写成整个“支付系统由支付平台乙组维护”。实例职责不能证明系统整体职责。
3. B/Q086把2025旧职责终止与另一文件的2026甲组登记拼成“历史变更记录显示……由基础设施甲组承接”。2026甲组维护事实正确；明确承接过程没有记载，且history本身不含甲组。这项按严格明确原文口径保守计为轻微额外推断，未判定2026职责事实错误。
4. C/Q100在正确给出标记后又说信息或专用文档“由合规维护组负责管理”。原文只登记审计系统由该组负责，不能证明标记、信息或文档的管理职责；该句指代也不清楚。
5. D/Q055把特定缓存击穿流程写为可用于“缓存击穿等典型故障”。“等”扩大了故障适用范围；该手册没有给出其他故障的处理依据。所列缓存击穿步骤和备份正确，但不能推广到未登记故障。
6. D/Q093保留2027未知，仍额外把2026缓存实例职责改写成整个支付系统职责，与A/Q093同类。

这些断言保留原文与严重程度解释；没有通过删除问题句或不断修改prompt、重跑直到满分来覆盖失败。B/Q086属于推断边界，D/Q055属于故障范围边界；报告说明这一判读口径，便于复核者提出异议，而不将它们伪装成确定的事实矛盾。
