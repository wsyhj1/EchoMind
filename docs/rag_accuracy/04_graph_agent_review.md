# GraphRAG 独立子代理审查

- 审查日期：2026-10-23（Asia/Shanghai）。
- 审查者：Codex 子代理 `/root/graph_review`。这是代理审核，不是人类审核，不能改写为人工签核。
- 范围：`backend/graph/`、`backend/graph_cli.py`、迁移 003、上传/删除接入、运行开关，以及相关现有测试和运维文档。
- 不修改真实知识库、不进行真实回填、不运行云模型；数据库回归测试使用随机 schema，结束后清理。

## 结论

可以继续在已确认的本地用户/知识库范围内执行受控启用。当前实现具备有界图谱召回、失败回退、租户及知识库约束和可恢复索引。发现的两项回填运维缺陷已修正并加入回归测试。

这份审查不证明真实业务答案准确率，也不代表可直接开放公网多租户服务。现有合成数据集、图谱证据完整率和代码隔离检查不能替代业务答案审核。

## 已确认的机制

1. 图实体 ID 包含用户、知识库、类型、名称和限定词；关系两端、证据父块、作业均有对应复合外键。在线 SQL 先限制 user/KB，再链接实体和路径；默认知识库只扩大当前用户的检索范围，实际路径仍在单个真实知识库内连接。
2. 在线路径要求当前 extraction version、READY 作业、实际存在的父块和仍可定位的 quote。缺表、图谱超时或异常回退原有检索。固定方向模板最多 2 跳、3 种子、20 条关系、5 个图证据父块，默认图调用总预算 400 ms。
3. 发布在一个事务中再次核对租约、父块身份及全文；整文件抽取成功后才置 READY。取消或崩溃保留租约，过期可恢复，迟到发布失效。普通回填不会将 FAILED 默默重置为成功。
4. 上传在原有向量及父块处理后入队；抽取入队失败不伪装为图谱 READY，显式回填可补偿。删除事务级联图证据，并保留 Milvus 删除补偿；待清理状态阻止新上传/同名重建，自动重试有次数上限。
5. 抽取每个父块最多 2 次模型请求、每次默认 30 秒，默认并发 4；单文件最多 1000 父块，模型结构最多 48 实体/64 关系。CLI 单批文件数为 1..100，默认 20。

## 发现与处理

### 已修正：选中文件与实际认领文件不一致

原 CLI 按 file_hash 选择 N 个文件后，仅按用户/知识库调用 `run_pending(limit=N)`；实际认领按作业创建顺序，可能处理计划之外的旧 PENDING 文件，导致输出和本批操作不一致。

现已通过 `execute_backfill` 逐个使用选定 file_hash 认领，每个文件最多一次；模型失败后停止本批，未开始的文件不会提前入队。既有 READY 跳过和显式 force 规则保留。

### 已修正：FAILED/STALE 占据普通小批量回填名额

原 `backfill_files` 将所有非 READY 文件都计入 LIMIT；FAILED 无法自动认领却会一直排在后续文件前，导致重复执行小批量时无法推进。

现普通批次选择未索引、PENDING 和过期 RUNNING，FAILED/STALE 需显式 force 且不占普通批次。活跃 RUNNING 不会被 force 抢占。过期且耗尽重试的租约会明确转为 FAILED；显式 force 可在同一选定文件范围内恢复它。

CLI 额外读取整个目标范围的状态，输出 `remaining`、`requires_force`、`complete`；`--file-hash` 同时约束状态统计。指定不存在文件会输出 `requested_file_missing=true`，不能报告完成。

- 退出码 0：目标范围全部 READY，或目标知识库没有源文件。
- 退出码 1：本次失败、需 force 的任务、选中文件未 READY，或指定文件不存在。
- 退出码 2：本批处理成功，但范围内仍有后续普通批次/其他进行中的任务。
- Dry-run 只输出计划，退出码仍为 0，不调用抽取模型。

### 运维文档应以个人设置优先级为准

`02_graph_reindex.md` 的旧回滚段只写服务端 `GRAPH_RAG_ENABLED=false`，容易被理解为强制关闭全部用户；个人明确保存的 true 会覆盖该默认值。实际应按 `03_rollout_and_rollback.md`，同时核对目标用户的 `graph_enabled`。图谱抽取开关是服务端开关；停掉它不会实时取消已开始的整文件任务，重启会取消后台任务并留待租约恢复。

开启自动抽取前应确认当前所有待处理队列，而不只查看本次指定知识库；后台 worker 的抽取范围是全部待处理用户，CLI 的范围才是指定用户/知识库。当前受控启用可先关闭自动抽取，仅显式回填，再决定是否启动后续上传抽取。

### 非阻塞限制：成本上限并非账单上限

现有次数、并发、文件数和超时约束避免无限循环，但单文件 1000 父块、每块 2 次请求仍可能产生较高成本。模型请求未设置显式输出 token 上限，也无每日账单熔断；响应后的 schema 限制不能限制模型已经生成的 token。先按实际父块量小批执行并观察费用；扩大规模前可增加输出 token 上限和每批请求预算。

抽取事实性仍依赖模型及保守文本验证，无法保证所有否定/历史/语义错误都被规则识别。跨年份长期运行时也应重新确认“当前事实”数据的有效期。应保留原文来源，不能把关系边直接当无条件真实答案。
