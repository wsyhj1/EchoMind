## 开发中实际遇到的问题

1. **后台模型限流**：最初使用的后台模型返回 429/APIConnectionError，16 文件首轮失败有完整记录。
   改用项目已配置且单份验证成功的主模型，新功能默认 `AGENT_BASE_MODEL`，仍支持独立覆盖；原聊天和记忆模型不变。
   失败批次不再连续消耗整个队列；FAILED 保留，显式重试，不掩盖成 READY。
2. **同一实体跨文档被拆开**：v1 将“独立实例”“实例”“青岚实例”等描述当作不同身份。
   v2 去除通用及与全名重复的限定词，保留地区等真实消歧信息。四个系统都形成了真实两跳路径。
3. **源文件重复去重丢来源**：原代码跳过跨文件相同子块。现在保留每个父块/文件的来源行，
   同父块去重、文件哈希去重和向量复用继续保留；真实 PDF/DOCX 删除检查证明另一份文件仍可检索。
4. **跨库删除非原子**：新增 PG 事务内的持久补偿任务，Milvus 失败仍返回错误，后台可重试，
   清理未完成时阻止同名重建/上传，避免迟到删除伤及新来源。
5. **源码父块更新后旧边残留**：在线每跳再次核对原文引用。引用失效立即舍弃路径，即使索引状态还未重建。

## 图索引与延迟

隔离语料的 v2：16 文件 READY；15 条关系证据，均重新通过最终校验器的引用、端点与类型检查。
v1 数据与失败报告保留用于诊断；在线按配置仅使用 v2。

云模型实测中图步骤 P50=9.26ms，P95=24.21ms；默认图查询预算 400ms。
A 总延迟 P95=8475ms，B=6231ms，但两次实验跨日期、服务负载不同，且 embedding/Reranker 时间也明显变化，
**不把总延迟下降归功于图谱，不据此承诺性能提升。**
后补的原文变化防护由独立集成测试和全量录制回放验证，最终严格 SLA 仍需在目标规模重新测量。
图查询本身不额外调用 LLM；离线抽取的完整 Token/费用没有采集，不填成零成本。
