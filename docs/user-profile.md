# 用户画像（第一版）

侧栏「我的画像 → 查看与编辑」可填写背景与经验、当前目标、关注领域和回答偏好。保存后从下一轮回答生效。

- 有任一手动字段时，仅使用手动画像；四项都为空时，回退到已有自动摘要。
- 「使用画像回答」控制画像注入，不关闭会话上下文或独立的长期记忆检索。
- 面板「设置 → 自动更新画像摘要」独立控制后台画像更新，不影响其他记忆整理。
- 「清空画像」清除当前手动字段与自动摘要，同时暂停自动更新。历史对话、长期记忆以及已有评测快照不会被清除。
- 自动摘要仍按原规则在后台检查：每 180 秒一次，单个会话未整理内容超过约 1000 tokens 才提取。打开或编辑面板不会调用模型。

回答下方显示画像是否注入；「回答详情 → 个性化」记录当时的版本、来源与注入文本。记录注入不等于证明模型遵循了偏好。旧回答没有记录时会明确显示未知。

## 存储与接口

启动后自动运行 `backend/migrations/002_user_profile.sql`，为现有 `users` 表添加手动字段、两个开关、版本及时间，不改写旧自动摘要。旧摘要更新路径与手动内容分离，所有写入使用版本检查；后台迟到结果与失败回滚都不能覆盖更新的用户操作。

画像设置和每轮快照从 PostgreSQL 读取，旧 Redis 画像缓存仅用于兼容路径，自动更新与清空时使其失效。内容变化与设置变化均递增版本，内容更新时间和设置更新时间分别记录。

| 接口 | 用途 |
| --- | --- |
| `GET /user-profile?user_id=1` | 读取当前画像与设置 |
| `PUT /user-profile?user_id=1` | 提交 `fields` 和 `expected_revision` |
| `PATCH /user-profile/settings?user_id=1` | 提交开关和 `expected_revision` |
| `DELETE /user-profile?user_id=1&expected_revision=N` | 清空并暂停自动更新 |

版本冲突返回 409，用户不存在返回 404，非法字段或长度返回 422。接口沿用本地部署现有的 `user_id` 模式；本版不新增登录体系。

本版提供来源类型（手动/自动）与本轮注入快照；尚不提供自动摘要的逐条对话证据、逐项确认或完整版本浏览。
