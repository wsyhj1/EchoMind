# 第二阶段交付：持久站内提醒

日期：2026-10-28（Asia/Shanghai）。在已有项目工作台基础上增量实现；保留原工作区改动，没有提交或推送Git。

## 直接体验

打开 [EchoMind工作台](http://127.0.0.1:8501/?project=ae5530aa-2f4c-4c28-91aa-6d3c092ddfbe)，进入项目的「提醒」页，填写内容、提醒日期和时间，点击「设置提醒」。时间按Asia/Shanghai计算。

到期通知出现在顶部「提醒收件箱」。支持已读、打开项目和30分钟后提醒；项目提醒列表支持取消、分页与刷新状态。当前工作台每15秒检查收件箱，后端通常每5秒扫描到期事项。后台调度独立于浏览器，关闭网页后仍可入箱；后端或电脑停机期间无法实时送达，重启后补发。

学习顺序：先读[总体学习文档](personal-assistant-learning.md)，再读[持久提醒的技术路线与源码讲解](personal-assistant-reminders.md)。后者包含事务时序图、时区、重试、取消竞争、双worker以及四个动手实验。

## 已完成的可靠性行为

- 提醒与通知持久存储；插入通知和修改投递状态处于同一事务。
- 同一提醒的同一generation只保存一条通知，稍后提醒创建下一generation。
- 相同操作ID与原内容重试返回原回执；同ID不同内容拒绝。
- 所有用户操作校验项目、任务和资料范围，不允许借提醒读取其他用户的数据。
- 提醒使用独立版本；后台投递不修改项目版本、任务状态或模型候选。
- 到期检查最新状态，已归档项目、已完成/取消任务、不可用资料范围自动跳过并记录原因。
- 接受带明确偏移与匹配IANA时区的未来时间；拒绝无时区、非法夏令时时间、过期时间和超过365天的时间。
- 后端重启扫描未投递记录；后台异常保留待处理记录并重试，界面显示延迟心跳。
- 每项目最多100项待提醒事项；收件箱和提醒历史提供分页。

## 后续路线与明确边界

下一步先积累实际使用反馈：哪些提醒被已读、稍后提醒或取消，是否减少漏事，再决定重复提醒规则和通知渠道。现有已读与投递记录只能证明交互，不证明工作效率提升，不能直接编造采纳率或提升百分比。

本轮没有实现每日/每周重复规则、邮件、系统推送和外部日历；知识对话页暂不展示自动刷新收件箱。归档/完成抑制发生在到期检查时，已经投递的历史通知会保留。每轮100项、通常5秒扫描与15秒页面刷新是实现参数，不是实时SLA。

重启仍沿用 `start.ps1 -Service Databases`，然后在两个终端分别运行 `start.ps1 -Service Backend` 和 `start.ps1 -Service Frontend`。不需要新的依赖、云端服务或定时任务配置。
