# 多会话与上下文治理：首版交付记录

日期：2026-10-26。对应 [多会话设计](EchoMind_Multi_Conversation_and_Frontend_Design.md) 与 [ReAct 上下文计划](EchoMind_ReAct_Context_State_Loop_Engineering_Design.md)。本记录区分已实现内容与后续设计；不将显式任务状态图或耐久暂停/恢复标为完成。

## 已实现

### 会话与持久历史

- 新增 `009_conversations.sql`，建立 `chat_conversations` 和有序 `chat_turns`。conversation、turn、run 使用独立身份，关联现有 evaluation_runs；不改写旧 run、raw_conversations 或图谱数据。
- 同一知识范围可创建多条独立会话，支持列表、标题搜索、分页、重命名、归档与恢复。创建请求和发送请求分别使用幂等键。
- 会话绑定知识范围；新 URL 为 `?conversation=<UUID>`，兼容新制会话的旧 session 链接。切库导航不会直接改变既有会话范围。
- 接受用户消息与初始 run 在一个事务中写入；最终回答与运行终态在一个事务中提交。原始流片段在完成前属于待确认内容。
- Redis 只保存本轮 Agent 的执行状态；每轮使用独立 checkpoint thread。下一轮从 PostgreSQL 读取本会话历史，因此刷新或 Redis TTL 到期不再使新制会话丢失短期连续性。
- 旧 session 不自动回填到某个知识库；“更多 → 旧版历史会话”只读访问原记录，避免混合范围的旧聊天进入新上下文。

### 并发与执行边界

- 同一会话仅允许一个活动 turn，使用数据库行锁和唯一活动索引保护；不同会话可以独立执行。
- 相同 client_turn_id 和相同内容返回已有执行，不再次调用模型；相同 ID 的不同内容返回冲突。重复请求不会使用新的设置或预算重新执行。
- 重命名、归档和发送使用 revision 检查；活动执行期间不允许归档。其他标签页更新后，过期 revision 会被拒绝。
- 执行租约过期后标记失败，迟到结果不能提交成功。租约有效性使用 `clock_timestamp()`，避免等待行锁使事务起始时间延长租约。
- 准备、上下文读取和 Agent 处理纳入时间上限；上下文读取超时不启动模型。断线后可刷新核对，也可使用原发送标识重试。
- 服务端可限制同时执行的会话数量，默认每用户 4 个、服务合计 12 个。只短暂串行化额度预留，不将整个模型执行串行化。
- 与新制 turn 关联的 run 不能由旧运行删除接口单独删除，防止删除审计时连带破坏聊天历史。

### Contextual ReAct 基础治理

- 保留现有 `create_agent` 循环、模型调用预算和检索工具次数上限，没有额外嵌套一个 Agent 循环。
- 每次模型调用前生成 ContextPack：保留会话起点的用户原始目标、本轮完整消息和工具协议，按预算从最早的已完成历史对话对开始裁剪。近期历史最多读取 100 个已完成 turn；后续新要求优先于会话起点。
- 不将旧 ToolMessage、旧系统提示、旧技能或旧画像作为当前上下文重放。历史助手答案中的 E 编号在模型投影里替换为待核验标记；页面和原始记录仍保留原文。
- 一轮内的工具调用与结果必须完整配对，不能通过截断当前证据或丢弃半个工具协议来凑预算。当前必要内容超限时明确失败并提示缩小范围。
- 输入预算包含系统消息、消息内容、工具 schema 和协议安全余量。当前使用保守的 UTF-8 字节估算，默认输入估算上限 65536；输出上限仍由现有 ChatLimits 单独保留。该值不是模型窗口规格，也不是准确 tokenizer 计费结果，切换模型时需核对提供方限制。
- 新会话关闭旧自动模型摘要 middleware，以确定性投影管理窗口；这与长期记忆/画像开关分开。长期记忆开启时，成功消息生成兼容提取器的派生副本，chat_turns 仍为恢复历史的权威来源。
- 聚合知识范围在 turn 接受时记录授权库集合；检索候选在重排前过滤到本轮集合。模型使用资料前，核对实际工具 evidence、检索 trace 和当前数据库原文；来源变化或删除时停止生成。
- 新会话使用单独的系统规则，消除旧提示中“历史已有即可直接回答”和“事实必须检索”的冲突；画像只影响表达，资料与记忆不能修改身份和工具权限。

### 前端

- 继续使用 Streamlit，采用更紧凑的品牌区、侧栏会话列表和简洁聊天区。上传/图谱维护在“资料管理”，RAG、画像、记忆和模型服务仍在设置。
- 会话菜单支持新标签页打开、刷新当前会话、重命名、归档/恢复；更早消息按需分页加载。归档列表入口放在“更多”。
- 新对话先是本地空白页，首次发送时幂等创建。每个浏览器标签页管理一个活动会话；同一知识库的多个会话可分别打开。
- 流事件携带 conversation_id、turn_id、run_id；前端丢弃不属于当前会话的片段。未确认的发送可使用原 ID 重试。
- 已绑定会话的库不在本页目录缓存时，保留服务端核验过的绑定范围，不静默改选默认库；打开失败时清除旧聊天视图并阻止误发送。
- 原有 `/`、`&` 技能、引用详情及设置入口继续保留。

## 接口与配置

新增接口：

| 接口 | 行为 |
|---|---|
| `POST /conversations` | scope_id + client_create_id 创建会话 |
| `GET /conversations` | 按 scope_id / archived / search 分页列出当前用户会话 |
| `GET /conversations/{id}` | 会话元数据 |
| `PATCH /conversations/{id}` | expected_revision + title / archived |
| `GET /conversations/{id}/messages` | 有序消息分页，before 为 sequence |
| `POST /conversations/{id}/turns/stream` | query + client_turn_id + expected_revision，返回 NDJSON |
| `GET /conversations/resolve-session/{session_id}` | 原 session 链接到新制会话的映射 |
| `GET /conversations/legacy` | 旧 session 的只读目录，不执行归库迁移 |

所有接口经过应用现有身份中间件，并在存储查询中核对用户归属；客户端不能通过 URL 指定其他用户。目录游标携带翻页时确定的时间和 ID，并绑定用户与 scope，不重新读取游标行的可变时间。

新增配置已写入 `.env.example`：`CHAT_CONTEXT_INPUT_TOKENS`、`CHAT_MAX_ACTIVE_PER_USER`、`CHAT_MAX_ACTIVE_TOTAL`。本次不修改真实 `.env` 或用户设置。

## 验证记录

自动检查和浏览器验收的最终结果记录在 [验收结果](multi_conversation_delivery.acceptance.json)。测试使用隔离 PostgreSQL schema、假模型及已有隔离检索夹具，不依赖私人文档或真实生成服务。首次全量检查暴露的短时间窗测试问题保留日志；修正后重新验证。

子代理进行了两轮只读审核，提出并推动修复：范围与目录缓存不同步、可变分页游标、上下文读取未计时、不确定发送重试、以及等待行锁跨越租约到期时的迟到提交。

最终通过后端 223 项、前端 57 项检查。浏览器使用真实会话 API 和隔离数据库，完成同库双会话、刷新恢复、双标签页与手机布局验收；3次离线模型执行、0次外部提供方调用。本地后端已重启加载新增表，8501/8000健康；既有用户、知识库、文件、原文块和图谱指纹一致。临时8502/8812服务、3个经过表结构及测试身份核对的浏览器schema和临时浏览器页均已清理。

## 仍属后续工作

- 显式业务 TaskSpec、LoopState 状态图、暂停/继续、进程重启后从中间节点耐久恢复，仍按主计划 P2/P3 推进。首版中断后返回失败，不自动重放模型请求。
- 没有自动提取并永久保留所有历史约束。当前保留原始起点与预算允许的近期消息；结构化约束更新、人工固定上下文和语义压缩需另行实现与评测。
- 当前一个页面只运行一个活动流；本页回答期间禁用切换，其他会话可在新标签页使用。跨标签页结果通过刷新读取，尚无后台流订阅、应用内标签或分屏。
- 旧版历史入口最多展示最近 100 个 session，每个原 session 的现有 `/runs` 接口最多读取 100 个 run；原数据库记录未删除。新制会话有独立分页，不受这一展示限制。
- 当前引用结构/来源核对不等于语义蕴含验证。流式文本先展示，来源在模型调用前核对；完整的发布前校验与必要缓冲属于 P2。
- 未迁移 React，也没有声称复刻 Codex 的内部运行方式或保证无限长度的完整上下文。
