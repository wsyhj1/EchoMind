## 现在如何体验

本机前后端已加载本版实现，打开 [EchoMind 个人工作台](http://127.0.0.1:8501)。已有一个明确标注为示例的项目：[示例 · EchoMind 工作与学习](http://127.0.0.1:8501/?project=ae5530aa-2f4c-4c28-91aa-6d3c092ddfbe)。它的完成记录和笔记都是演示数据，不是用户实际工作成绩。

依次体验：查看项目目标 → 修改今天可投入的分钟数 → 看下一步建议及上次决定 → 在任务页添加/更新事项 → 记录进展或学习笔记 → 打开项目对话 → 返回项目 → 生成并下载近期复盘。

想理解实现，先读 [学习文档](personal-assistant-learning.md)，再对照 [技术路线](personal-assistant-plan.md)。建议先学事务、版本和幂等，再读Agent工具与上下文。

## 已实现

| 能力 | 实际行为 |
|---|---|
| 项目空间 | 自有项目、目标、固定资料范围、归档/恢复；默认进入个人工作台 |
| 工作/学习任务 | 标题、说明、类型、优先级、预计分钟和截止日期；开始、受阻、完成、重开、取消；完成/受阻必须保存依据 |
| 项目记忆 | 进展、决定、阻碍、学习笔记；明确更正关系保留旧记录与来源，不自动把相似度当事实更新 |
| 资料关联 | 自有范围内已有文档与HTTP(S)链接；检查当前目录来源是否仍存在，关联不代表已经读取正文 |
| 工作恢复 | 按用户时间预算提供最多三项规则建议；无耗时或预算不足时明确是启动/子步骤，不改任务状态 |
| 明确命令 | “新增任务：标题；预计30分钟；优先级高”“记录决定：内容”等直接持久保存；未识别属性整体拒绝，不悄悄丢弃 |
| 项目会话 | 同一项目可开多条会话；每轮服务端读取该项目最新状态，保留本轮快照；普通会话继续使用原流程 |
| 助手候选 | 项目工具读取状态或保存一项候选；可一次提出最多10项任务的原子计划；用户采纳后才变正式任务，旧版本候选不覆盖新状态 |
| 有依据复盘 | 根据指定窗口真实事件生成新增/完成/重开和学习记录；标用户报告、来源编号和截断边界，可导出Markdown |
| 可靠保存 | 用户与资料范围隔离、项目行锁和revision、操作指纹与持久回执、事务化事件；网络不确定时原请求重试 |

## 验证方法

新增测试位于：

- `backend/tests/test_personal_assistant.py`：输入约束、规则恢复、真实隔离PG中的重试/并发/回滚、资料范围、记录更正、候选与复盘。
- `backend/tests/test_personal_assistant_agent.py`：真实LangGraph执行图配离线模型；读取项目、保存成批候选、实际采纳；资料技能不新增候选写入工具；两个HTTP项目会话读取同一持久项目状态。
- `frontend/tests/test_personal_assistant_ui.py`：创建、保存、断线重试复用操作ID、HTML转义、复盘导出、过期候选、项目会话与重载导航。

统一回归命令：

```powershell
.\.venv\Scripts\python.exe scripts/run_checks.py --integration
```

## 演示初始化与重启

示例初始化可重复执行：

```powershell
.\.venv\Scripts\python.exe scripts/seed_personal_assistant_demo.py
```

已验证复跑后仍为4项任务、3条当前笔记，版本9；额外一条笔记来自浏览器的实际保存验收。脚本使用固定操作键，保留已存在进展，不重复创建任务。它只支持现有本机模式，不读取私人文档，不调用模型。

如果电脑或服务重启，先启动Docker Desktop，再启动现有数据库：

```powershell
.\start.ps1 -Service Databases
```

分别在两个终端运行：

```powershell
.\start.ps1 -Service Backend
```

```powershell
.\start.ps1 -Service Frontend
```

本次服务运行在隐藏窗口，仅监听127.0.0.1，PID记录沿用 `.runtime/backend.pid` 和 `.runtime/frontend.pid`。运行期间可直接访问工作台；关机或停止服务后，网页不会自行继续运行。项目和任务保存在数据库，重启服务后重新读取。

## 仍需后续验证与实现

- 没有通过本轮测试宣称真实模型规划质量、真实用户一周效果或生产SLA。离线工具调用成功不能替代真实模型质量评估。
- 表单、明确命令、恢复与事件复盘无需模型；自由项目对话沿用原配置模型，会产生正常服务用量。通用长期记忆开关与显式项目状态分别管理。
- 恢复建议目前是可检查的规则基线，可能需要用户调整任务范围和估时；预计分钟不是实际工时。
- 第一版按项目整体revision串行修改，两个独立任务同时编辑也可能冲突；当前采取刷新核对，后续按并发需求决定是否拆分版本。
- 记录和候选设有上限；历史事件可分页，报告超出1000条时明确截断。未实现无限历史自动压缩与全库遍历。
- 下一阶段是用户设定的持久提醒、通知渠道及日历接入，需要进一步实现时区、取消、重启补偿和投递幂等；当前没有把这些能力做成占位承诺。
