# EchoMind 技能与命令

技能是应用内注册的本轮工作流。它让同一问题按摘要、对比、查证等方式执行，使用现有知识库、检索工具、引用核验和账号权限。技能不执行终端命令，不修改个人设置，也不替代来源证据。

## 使用

输入框输入 `/` 或 `&` 可展开技能菜单，继续输入名称可筛选。用上下方向键移动，Enter或Tab填入命令，Esc收起；选择不会自动提交。补上主题后，再按Enter发送。中文输入法选字期间不处理技能快捷键。

也可以直接输入完整命令，英文和中文别名均可：

| 命令示例 | 用途 |
|---|---|
| `/summary 检索质量` 或 `&摘要 检索质量` | 从实际检索资料中提炼要点、限制与来源 |
| `/compare 方案A与方案B` 或 `&对比 方案A与方案B` | 按共同维度列对比表，保留分歧和缺失信息 |
| `/evidence 这项方案是否已经上线` 或 `&查证 这项方案是否已经上线` | 对照证据区分支持、反驳与无法确认 |
| `/outline 项目介绍` 或 `&大纲 项目介绍` | 根据已取得的材料整理有层次的大纲 |
| `/review 实验结论` 或 `&审阅 实验结论` | 检查证据缺口、实验口径与过度主张 |
| `/explain 父子分块` 或 `&解释 父子分块` | 解释概念、步骤与例子，区分资料事实和说明性示例 |

摘要和大纲允许省略主题，但只能处理本轮实际检索到的材料。其他四项需要明确问题或主题，缺少时会提示补充，不发起模型请求。单次Top K检索不能视为已经阅读全文或整个知识库。

`/help`、`/skills`、`/帮助`、`/技能` 打开「设置 → 技能与命令」；也可从侧栏「更多 → 技能与命令」进入。`/settings`、`/设置` 打开现有设置中心；`/new`、`/新对话` 开始新会话，原会话可从会话列表或原链接打开。它们均在界面本地处理，不生成模型回答，`&`前缀同样适用。

只解析消息开头的命令，正文中的`R&D`等不受影响。未知名称会提示，不交给模型猜测；URL/文件路径按普通文本处理。以`//`或`&&`开头可按普通文本发送，而不执行对应技能。

## 执行边界和审计

前端只发送原始命令文本。服务端重新解析并确定canonical skill_id、主题及版本，从受信任注册表读取工作流；浏览器不能注入技能instructions或通过额外参数切换身份和范围。

技能只对当前轮生效，普通下一轮恢复普通工作流。运行记录保留原始命令，config中保存技能ID与版本；实际模型输入保留工作流的注入证据。技能名称显示于已保存回答下方。历史引用仍按当前原文状态单独核验，技能不会把结构核验冒充语义正确率。

注册表公共接口 `GET /skills` 只返回名称、别名、说明、示例和所需参数等元数据，不返回工作流instructions。接口沿用应用身份中间件。

当前扩展方式是本机维护受信任注册表并重启应用；不提供远程上传任意脚本或从文档中自动安装技能。

## 注册新技能

在 `echomind_skills/catalog.json` 的skills数组中增加声明：设置唯一英文id、中文name、description、中英文aliases、examples、kind、requires_input、default_input、action和workflow。普通技能使用 `kind:agent`、`action:run`，workflow是具体步骤字符串数组。必填输入时default_input必须为空；可省略输入时提供合理默认主题。本地动作只允许现有help/settings/new_chat三项。

英文id和别名必须全局唯一；别名不带`/`或`&`，两个前缀由解析器统一处理。示例必须属于本技能，不能调用其他命令。注册表检查字段、长度、重复名和动作类型，非法声明会阻止加载，而不会静默覆盖已有技能。

共享policy、技能定义及workflow一起计算canonical JSON SHA256，版本随内容变化。修改后重启后端和前端，让提示、命令目录和记录版本保持一致。可运行：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s backend/tests -p test_skill_registry.py -v
.\.venv\Scripts\python.exe scripts/run_checks.py --integration
```

菜单是原生聊天输入框的渐进增强；普通文本提交仍由原生输入框处理。若未来Streamlit更改输入框DOM，完整命令和「技能与命令」帮助入口仍可使用，菜单组件需要按对应版本复验。
